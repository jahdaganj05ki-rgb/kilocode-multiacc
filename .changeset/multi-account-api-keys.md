Use several API keys per provider: add, label, verify, enable/disable and choose the active key, with manual, failover-on-error/quota or round-robin-per-turn switching. The account dialog now shows when each key was used, its token/cost usage and a live cooldown countdown, can reorder keys for failover and verifies all keys at once. Saving, removing or switching the active account merges into the stored accounts, so health updates of a running server are never overwritten. A rate-limited verification benches the key for the advertised retry-after window (at most one hour), like a throttled turn does; a provider whose only key is cooling still uses it instead of failing. Manage them with `kilo auth account list|add|remove|activate|enable|disable|strategy|verify --provider <id> [--json]` (verify accepts `--all`), and pass `--account <id|label>` to `kilo auth login` to replace one account's key. `kilo auth account add` prompts for the key when it is omitted, so it stays out of the shell history; labels must be unique per provider so `--account` stays unambiguous. Providers that report their rate-limit quota in response headers get it stored per account: a key with no requests left is skipped until it resets, and the dialog shows the remaining requests and reset countdown next to the usage line, with **Use anyway** to activate a cooling or rejected key on purpose. See the new *Multiple API Key Accounts* docs page.
